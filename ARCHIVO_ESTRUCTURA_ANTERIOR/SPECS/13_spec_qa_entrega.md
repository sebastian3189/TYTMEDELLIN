# ARCHIVADO — Spec 13 anterior

## Regla de estado

Todos los SPECS parten como pendientes. Nada heredado se considera terminado. La
evidencia de esta nueva aplicación determina el estado de cada compuerta.

## Matriz funcional

- Navegación, menús, breadcrumbs y 404.
- Listados y detalles con datos completos y parciales.
- Cotización: válido, inválido, duplicado, sin red y error de servidor.
- WhatsApp con contexto correcto.
- Consentimiento: aceptar, rechazar y modificar.
- Contactos, enlaces externos y descarga si existe.

## Matriz visual y accesible

- Viewports: 320, 360, 390, 768, 1024, 1280, 1440 y 1920 px.
- Navegadores vigentes basados en Chromium, Safari y Firefox.
- Teclado, foco, zoom 200 %, movimiento reducido y lector de pantalla.
- Contraste, headings, labels, errores e imágenes.

## Matriz técnica

- Build limpio y sin errores de consola.
- Rutas directas y recarga funcionan en producción.
- Sitemap, robots, canonical, metadatos y datos estructurados.
- Core Web Vitals del Spec 10.
- Validación de servidor, rate limit, permisos y cabeceras.
- Eventos sin duplicados y sin datos personales.
- Estado del guard Higgsfield con consumo confirmado más reservas ≤ 200 créditos.
- Movimiento web probado en móvil, teclado y `prefers-reduced-motion`.

## Revisión de contenido

- Solo Medellín y cobertura aprobada.
- Cero `PENDIENTE CLIENTE`, lorem ipsum o datos de muestra publicados.
- Ortografía, teléfonos, horarios, enlaces, imágenes y consentimientos aprobados.
- No existen afirmaciones, testimonios o logotipos sin autorización.

## Severidad

P0 bloquea uso o expone datos; P1 rompe un flujo principal; P2 degrada una función;
P3 es mejora menor. El lanzamiento requiere cero P0 y P1. Los P2 aceptados deben
tener responsable y fecha.

## Entrega

Se entrega URL de producción, acceso del propietario, repositorio sincronizado,
variables documentadas sin secretos, inventario de integraciones, guía de edición,
respaldo y evidencia de las pruebas.
