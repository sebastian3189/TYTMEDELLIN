# ARCHIVADO — Spec 01 anterior

**Producto:** Transporte y Turismo Medellín (T&T Medellín)  
**Estado:** Por iniciar  
**Construcción:** Desde cero  
**Fecha:** 11 de octubre de 2026

## Decisión de alcance

La aplicación representa únicamente la operación de T&T Medellín. No se parte de
una interfaz, arquitectura, backlog o código anterior. Todo el contenido, navegación
y conversión se concentra en esta operación local.

Los SPECS definen el resultado esperado y sus criterios de aceptación; no describen
arreglos sobre una aplicación heredada ni imponen una plantilla o constructor visual.

## Objetivo

Crear una experiencia web confiable y móvil que permita entender la oferta local,
explorar servicios y experiencias, conocer la capacidad operativa y solicitar una
cotización contextual por formulario o WhatsApp.

## Audiencias

| Audiencia | Necesidad | Conversión |
|---|---|---|
| Empresas y agencias | Operación confiable y capacidad | Solicitar propuesta |
| Viajeros y grupos | Traslados y experiencias claras | Cotizar |
| Eventos | Coordinación de personas y vehículos | Pedir asesoría |
| Hoteles y aliados | Operador local recurrente | Contacto comercial |

## Primera versión

- Inicio orientado a confianza y conversión.
- Servicios de transporte.
- Flota o tipos de vehículo, con datos confirmados.
- Experiencias operadas desde Medellín.
- Detalles de servicios y experiencias.
- Nosotros, contacto, cotización y privacidad.
- WhatsApp contextual.
- SEO local, analítica consentida, accesibilidad y responsive.

Fuera del alcance inicial: pagos, reserva con cupos en tiempo real, cuentas de
usuario, aplicación nativa, marketplace y panel administrativo personalizado.

## Principios

1. Medellín es el único contexto geográfico.
2. La confianza verificable prevalece sobre frases promocionales.
3. Cada pantalla tiene una acción principal clara.
4. Se diseña primero para 360–390 px.
5. Los datos faltantes se marcan `PENDIENTE CLIENTE`; nunca se inventan.
6. WCAG 2.2 AA se incorpora desde los componentes.
7. La identidad debe ser propia, no una adaptación superficial de una plantilla.

## Fases y compuertas

| Fase | Resultado | Aprobación necesaria |
|---|---|---|
| 0. Descubrimiento | Oferta, datos y activos | Inventario validado |

| 2. Estructura | Mapa, flujos y wireframes | Cotización validada |
| 3. Sistema visual | Tokens, componentes y prototipos | Inicio móvil/escritorio |
| 4. Construcción | Aplicación funcional | Alcance completo |
| 5. Integraciones | Formularios, medición y SEO | Pruebas técnicas |
| 6. Lanzamiento | QA y producción | Spec 13 aprobado |

## Datos que debe entregar el cliente

Logo y marca, contactos, datos legales, WhatsApp, servicios, cobertura exacta,
flota, fotografías, experiencias vigentes, testimonios autorizados, destinatario de
formularios, dominio y accesos de medición.

## Aceptación global

La versión inicial se entiende inequívocamente como una aplicación nueva de T&T
Medellín y permite completar una solicitud real desde móvil sin publicar información
no validada.
